# 复盘

难点是将模型决策与业务约束分开：模型根据工具结果选择后续动作；代码负责确认边界、冲突复查、去重和实际保存结果。待确认的候选时间不提前占位，确认时必须重新检查。

实践中需要分别表达“草稿已保存”“建议待确认”和“当前时段冲突”：外部排期更新后，旧草稿仍然存在，但不能因此宣称排期可用。同一批建议需要互相避让，同时不能把待确认建议当成跨请求的全局占位。真实模型调用和可重复的离线回归测试分别提供不同的验证证据。

项目使用合成素材与规则，不能代表真实内容审核能力；本地 SQLite 不是生产排期系统。候选时段只搜索有限窗口；未命中时需要扩大搜索或由用户重新指定。GLM 接口的连通性、套餐适用范围和真实业务准确率是不同问题。

后续可根据真实业务规则扩展审核数据、候选时间策略和平台集成，并针对真实素材建立独立评估集。

实际用时与本次执行记录见 [评估文档](03-evaluation.md)。

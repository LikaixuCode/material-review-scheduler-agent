# 设计与取舍

## 调用链

CLI 验证输入并登记请求 → Claude Agent SDK 将业务工具提供给 GLM → 模型选择工具并读取结果 → 业务层检查规则和时间区间 → SQLite 保存草稿 → 程序按实际结果组装输出。

SDK 的 `@tool` 和 `create_sdk_mcp_server` 将 Python 函数注册为进程内工具。`tools=[]` 移除内置工具，`strict_mcp_config=True` 和 `setting_sources=[]` 避免加载额外工具配置。`max_turns=12` 限制 Agent 轮数；它不是工具调用次数的统计值。SDK 版本及其内置运行时在依赖锁文件中固定。

## 业务边界

- 素材工具读取合成元数据；规则工具检查必填字段、版权与禁用词；时段工具查询原定时间或有限数量的候选时间。
- 候选时段以请求时长为步长向后检查，最多检查八个位置并返回前三个可用结果；没有结果不代表更远的时间一定不可用。
- 输入和现有排期使用带时区的时间。同一渠道的时间区间发生重叠时视为冲突，不同渠道相互独立。
- 保存前重查审核和时段。当前无论 `hard_time` 取值如何，与原定时间不同的建议都标记 `pending`，不占位；明确确认后重新检查并占用本地时段。
- SQLite 通过请求内容校验、唯一约束和事务实现重复请求防重。确认和保存都只操作本地草稿。
- 输出中的保存状态来自存储结果，不能由模型自行宣称。工具失败会反馈给模型；失败或轮数用尽时输出未完成状态。

## 模型与离线模式

真实模式使用 Claude Agent SDK 调用 GLM，Trace 记录工具实际执行结果和模型给出的简要调用依据。离线模式由脚本按工具结果选择下一步；它复用同一业务代码，但不能说明真实模型表现。

GLM Coding Plan 的 Claude Code 兼容接口可用于本项目的技术测试，SDK 业务应用是否属于套餐支持范围需以智谱规则为准。
